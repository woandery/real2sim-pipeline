# 代码审阅记录

下面记录主 agent 对本项目实际代码的分轮检查，不冒充独立审阅者或真实模型 API 调用。

## 第一轮：契约、恢复与证据绑定

已修复：

- `drive=null` 在过滤空字段时会被移除，导致编译器恢复旧默认驱动。现在单独保留空驱动，并有回归测试。
- 运动补帧预算为 0 时仍可能加入一帧。现在在加入前检查预算。
- 审阅次数不能跨几何版本累加；现在要求同一版本连续通过，修复后重新计算。
- 缓存调用绑定完整 prompt、图片哈希、模型和结构，输出内容也绑定哈希。
- 关节初始锚点在 CPU 上核对，不能把不一致的规格交给 GPU 再试。
- 编译器初始状态与检查状态分离问题：初态不能重新指定姿态；导出前恢复初态连接启用情况。

## 第二轮：原生证据与失败行为

已修复：

- 不能只检查 sweep 目标值：现在检查测得的终点，角度和长度采用不同容差。
- 不能用外层步数推断实际积分：检查原生时钟和步数记录。
- 每次物理报告必须覆盖请求的状态，动态物体必须保持刚体、重力和碰撞；装配诊断中的外部支撑父体是显式例外。
- 原生代码变化后不能使用旧批准录制；录制前再次核对编译器及助手文件哈希。
- 网络/本地解析中断可能已经产生服务端费用；保持不确定状态，恢复时不自动重复调用。
- 第一次源码打包遗漏示例和文档；增加显式源码清单。

仍需继续检查：完整录制与交付状态恢复、装配验证新增路径、历史专用探针迁移、真实 API 输出规模/耗时，以及移植后的真实 GPU 执行。

## 第三轮：专用诊断与实际输入证据

已修复并增加反例测试：

- 杯盖检查不再绑定四个历史物体名称或内置半径；所有指定表面点必须出现一次，缺失、重复、错误物体、非有限误差都不能通过。
- 六角接口检查逐项检查正反转、目标实际旋转、平移、接触冲量与五组插入间隙，不能只看总 `passed` 标记。
- 装配检查逐连接复算保持/独立释放条件，并移除工作器内“四个连接”的数量假设。当前子体落地间隙方法只支持盒状碰撞器，提前拒绝其他类型。
- 球体检查必须与计划指定的实际支撑碰撞器一致，并检查逐步间隙和正接触冲量。
- 全程持物或腾空的视频可没有静置项，但仍必须有可执行的专用物理诊断；每个状态均有排除理由。
- 子进程移除自定义凭据变量和 `PYTHONOPTIMIZE`，防止泄露密钥或绕过原生断言。实际 CPU 子进程测试覆盖完成缓存、非零退出、超时和未知运行状态。
- API 请求预算考虑 Base64 膨胀；实际 SDK 的视觉/严格 JSON 协议在 MockTransport 上测试。
- 最终交付绑定人工批准文件。理解、几何和审阅不能引用未实际传入的证据帧；最终视频审阅保留全部补帧图像，避免隐藏物体证据丢失。

本轮还加入真实 GPU 验证，已经观察到原生编译渲染成功以及随后 Kit 启动崩溃。后者没有被缓存为成功，诊断与新尝试分目录保留。最终状态见验证记录；此处不将代码审阅等同于物理通过。

## 第四轮：交付前检查

已完成 10 个历史几何契约回归、57 项 CPU 测试、五类真实 GPU 诊断和独立只读哈希/数值复核。已在全新隔离环境从 wheel 安装并在源码目录外运行 CLI。新增运行期间冻结源码变化检测，球体接触对象使用准确路径匹配。源码分发包检查要求文档/示例/脚本完整，排除凭据、私有绝对路径和数据集视频。

首次 Kit 启动崩溃及后续独立通过均保留，不把根因未知的问题描述成已修复。真实 API 调用按项目所有者决定暂不执行，后续配置凭据时应运行 `api-smoke` 和实际视频流程。
