# 架构与审阅协议

控制端使用 OpenAI SDK 的 `responses.parse`，通过 Pydantic 生成严格 JSON Schema。证据帧只能引用已实际提供的帧，补帧图像持续参与最终录制审阅。图片以 Base64 输入，按“源时间线→补帧→原生渲染”的顺序传入。模型名、审阅模型、输出预算和超时均可配置。每个调用记录输入指纹、图像哈希、模型、输出、usage 和 API response ID；密钥只从环境读取。

模型负责理解、建模提案和视觉判断。程序负责执行、边界检查和验收约束。模型的“通过”不能覆盖程序检测到的错误。几何采用米制、Z 向上，包含真实空腔、刚体、碰撞及显式关节驱动；质量和材质均为待标定先验。

## 状态机

1. 固定源视频与配置哈希，完整解码并生成有序时间线。
2. 输出完整物体、初末状态和动作区间；补帧循环在预算内持续进行。
3. 输出场景和验证计划，验证 ID、引用、数值、关节拓扑与状态覆盖。
4. 原生编译、渲染和验证。每个版本使用独立目录，不覆盖旧证据。
5. 同版本进行至少两次独立视觉审阅；任一轮发现中/高严重性问题即进入下一版修复。
6. 通过的版本仍需要实际审图记录；批准绑定规格、模型调用、渲染和物理证据。
7. 冻结输入重新录制，完整解码，再审阅实际视频帧。

`needs_attention` 是可诊断的终止状态，不是成功。缺少物理能力、证据预算不足、连续审阅未通过、未知 API 完成状态均保留记录。

## 恢复与并发

每个运行目录使用进程级文件锁；GPU 工作器共享配置的设备锁。模型调用只有在指纹和结果哈希相同时才使用缓存。API 超时保留 `uncertain`，只有显式 `--retry-uncertain` 才能重试；这可能产生额外费用。原生任务失败或遗留运行状态不会自动重投，需要先检查日志和进程。

项目当前在 GPU 主机本地执行，不依赖 Inspire 账号、Notebook 名称、SSH 密钥或研究者的绝对路径。远程调度可在外层脚本中完成。

## 不能由当前证据支持的结论

程序验证的是有界诊断条件下的场景与资产。静置检查不能证明抓取成功；关节目标驱动不能证明机器人开盖；场景视频不能证明 PPO 学会了任务。视觉重建保留尺寸、隐藏结构和物性不确定性，不将模型猜测表述为测量结果。

## 当前 API 验证决定

按项目所有者要求，API 密钥先留空。官方 SDK 的请求/解析路径已有离线协议测试；真实模型权限、计费、响应质量与端到端生成效果尚未测试，不能由模拟 HTTP 测试推断。模型名在配置示例中保留占位符。
